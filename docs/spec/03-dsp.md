# 03 DSP

All processing is `double`. `fs` is the processing sample rate, `w0 = 2*pi*f0/fs`.
Numeric constants marked *(tune)* are starting points to be settled by listening
and measurement; everything else is normative.

## 1. Design principle

Every band is defined by an **analog prototype** `H(s)`. The UI draws the prototype
magnitude. Each digital realisation (IIR, FIR) is designed to match that magnitude,
so there is one source of truth and no high-frequency cramping.

Effective values used for design, after gain scale (02 §4.1):
`G = gain * scale` in dB, `A = 10^(G/40)`, `g = 10^(G/20)`.

## 2. Analog prototypes

Normalised frequency `s' = s / w_c`. `B_N` denotes the Butterworth poles of order
`N` on the unit circle: pairs with `Q_k = 1 / (2 sin(pi (2k-1) / (2N)))`,
`k = 1..floor(N/2)`, plus a real pole at -1 when `N` is odd.

| Shape | Order from slope `S` | Prototype |
|---|---|---|
| Low Cut | `N = S/6` | `s'^N / prod(B_N)` |
| High Cut | `N = S/6` | `1 / prod(B_N)` |
| Low Shelf | `N = S/6` | zeros = `r * B_N`, poles = `B_N / r`, `r = g^(1/(2N))`, evaluated in `1/s'` (mirror of high shelf) |
| High Shelf | `N = S/6` | `prod (s'^2 r^2 + (r/Q_k) s' + 1) / (s'^2 / r^2 + s'/(r Q_k) + 1)`; real root for odd N: `(r s' + 1) / (s'/r + 1)`. DC gain 1, HF gain `g`, gain `sqrt(g)` at `w_c` |
| Tilt Shelf | `N = S/6` | High Shelf with the same `g`, multiplied by `1/sqrt(g)` |
| Bell | `M = max(1, round(S/12))` | Order-`M` low shelf of gain `g` (DC gain `g`) mapped low-pass to band-pass `s' -> Q (s' + 1/s')` |
| Notch | `M` as Bell | Order-`M` Butterworth low-pass mapped to band-stop `s' -> 1 / (Q (s' + 1/s'))` |
| Band Pass | `M` as Bell | Order-`M` Butterworth low-pass mapped to band-pass |
| All Pass | 1 if `S = 6`, else 2 | `(1 - s')/(1 + s')` or `(s'^2 - s'/Q + 1)/(s'^2 + s'/Q + 1)` |
| Flat Tilt | fixed | Target `dB(f) = (G/6) * log2(f/f0)`. Realised as 14 first-order high shelves at `5 * 2^k` Hz, `k = 0..13`, each of gain `G/6` dB, plus a trim so the response is 0 dB at `f0`. Error budget ±0.25 dB, 20 Hz to 20 kHz |

Notes:

- For `M = 1` the Bell reduces to the classic
  `(s'^2 + (A/Q) s' + 1) / (s'^2 + s'/(A Q) + 1)`.
- Band transforms: each low-pass-domain root `p` yields band-pass roots
  `s = p/(2Q) ± sqrt((p/(2Q))^2 - 1)`; pair complex conjugates into second-order
  sections. An order-`M` bell therefore uses `M` biquads; a 96 dB/oct bell uses 8.
- **Q on cuts**: every section `Q_k` is multiplied by `(q / 0.7071)^(1/n)` where `n`
  is the number of second-order sections, so the gain at `f0` is `20 log10(q)` + 3 dB
  relative to Butterworth. `q = 0.7071` is exactly Butterworth.
- **Q on shelves**: the same scaling with reference 1.0 (`q = 1` is maximally flat).
- **Brickwall** (cuts only): order-12 elliptic prototype, 0.05 dB pass-band ripple,
  100 dB stop band, stored as a table of normalised poles and zeros generated by
  `tools/gen_elliptic.py` (scipy `ellipap`) and checked into `src/dsp/design`.
- Maximum sections per band: 16. The largest in use is Flat Tilt with 14; an order-8
  bell, notch or band pass uses 8.

## 3. Matched digital design (zero-latency and natural modes)

Each analog second-order section
`H(s) = N(s) / (s^2 + (wp/Qp) s + wp^2)` becomes one digital biquad
`(b0 + b1 z^-1 + b2 z^-2) / (1 + a1 z^-1 + a2 z^-2)`.
Method: impulse-invariant poles, numerator fitted to the analog magnitude at three
frequencies (after Vicanek, "Matched Second Order Digital Filters", 2016).

**Poles.** With `w = 2*pi*wp_hz/fs` clamped to `0.98*pi`:

```
a2 = exp(-w / Qp)
a1 = -2 exp(-w / (2 Qp)) * cos (w * sqrt(1 - 1/(4 Qp^2)))     if Qp > 0.5
a1 = -2 exp(-w / (2 Qp)) * cosh(w * sqrt(1/(4 Qp^2) - 1))     otherwise
```

**Magnitude basis.** For any `c0 + c1 z^-1 + c2 z^-2`, with `p1 = sin^2(w/2)`,
`p0 = 1 - p1`, `p2 = 4 p0 p1`:

```
|C(e^jw)|^2 = C0 p0 + C1 p1 + C2 p2
C0 = (c0 + c1 + c2)^2     C1 = (c0 - c1 + c2)^2     C2 = -4 c0 c2
```

**Fit.** Let `T(f) = |H_analog(j 2 pi f)|^2`. Compute `A0, A1, A2` from
`(1, a1, a2)`, then

```
B0 = A0 * T(0)
B1 = A1 * T(fs/2)
B2 = (T(fc) * (A0 p0c + A1 p1c + A2 p2c) - B0 p0c - B1 p1c) / p2c
```

where the fit point `fc` is the section's zero frequency `sqrt(n0/n2)` when it has
two finite zeros, otherwise its pole frequency, limited to `0.45 fs`.

**Recover the numerator** (minimum phase, `b0 > 0`), possible when `W^2 + B2 >= 0`:

```
W  = (sqrt(B0) + sqrt(B1)) / 2
b1 = (sqrt(B0) - sqrt(B1)) / 2
b0 = (W + sqrt(W^2 + B2)) / 2
b2 = -B2 / (4 b0)            (b2 = 0 if b0 == 0)
```

**Special cases**, checked before the general fit:

| Section | Numerator |
|---|---|
| All-pass | Reversed denominator (exact) |
| Zeros on the imaginary axis (notch, elliptic) | `k (1 - 2 cos(wz) z^-1 + z^-2)`, so the null is exact; `k` matches DC or Nyquist, whichever is larger |
| Numerator `s^2` (low cut) | `k (1 - 2 z^-1 + z^-2)`, both zeros at DC so the stop band keeps its slope; `k` by least squares |
| First order | Exact match at DC and Nyquist |

**Fallback** when `W^2 + B2 < 0` (the three targets cannot be met by a real
numerator): map the zeros with the same impulse-invariant formula as the poles and
fit one gain by relative least squares on 24 log-spaced points up to `0.95 Nyquist`.
Never clamp `B2` to `-W^2`: that puts the zeros on the unit circle and creates a
notch the prototype does not have.

**Orientation.** For gain-type shapes only one gain direction is designed with the
method above; the other is its exact inverse (numerator and denominator swapped).
The direct direction is the one whose poles are lower in frequency and more
resonant, where impulse-invariant poles are most faithful: the boost for Bell, Low
Shelf and Flat Tilt, the cut for High Shelf and Tilt Shelf. A boost followed by the
same cut is therefore flat to rounding error, at every sample rate.

**Measured accuracy** (worst `|digital - analog|` up to 20 kHz where the prototype
is above -40 dB; sample rates 44.1, 48, 96 kHz; all slopes):

| Shape | Typical: `f0 < fs/10`, Q 0.7 to 4, ±9 dB | Every setting up to `0.46 fs`, Q 0.3 to 12, ±18 dB |
|---|---|---|
| Bell | 0.31 dB | 4.8 dB |
| Low / High / Tilt Shelf | 0.35 dB | 9.7 dB |
| Low Cut | 0.38 dB | 5.2 dB |
| High Cut | 1.11 dB | 14.9 dB |
| Notch | 0.75 dB | 14.9 dB |
| Band Pass | 5.06 dB | 15.3 dB |
| Flat Tilt | 0.35 dB | 0.72 dB |

For ordinary 12 dB/oct bells and shelves (Q 0.7 to 4, ±9 dB) at 44.1/48 kHz the
error grows with frequency: under 0.01 dB below 400 Hz, about 0.3 dB around 4 kHz,
about 1 dB around 9 kHz and about 2 dB around 15 kHz.

The original target (±0.1 dB to half Nyquist, ±0.5 dB to 0.9 Nyquist) is **not
met**. The remaining error comes from the denominator: a section whose poles sit
near or above Nyquist aliases, and a two-zero numerator cannot fully repair it.
High Cut and Band Pass figures are dominated by deep stop-band points (-25 dB and
below). This is research item R-6. The unit test `matched design follows the analog
prototype` guards the figures above against regression.

## 4. Kernel: state-variable form

The matched biquad is run in a trapezoidal state-variable structure, which behaves
better than direct forms when coefficients move (dynamic bands, automation).

Map `(b0, b1, b2, a1, a2)` to SVF parameters:

```
g  = sqrt((1 + a1 + a2) / (1 - a1 + a2))
D  = 4 / (1 - a1 + a2)
k  = (1 - a2) * D / (2 g)
cL = (b0 + b1 + b2) / 4     cH = (b0 - b1 + b2) / 4     cB = (b0 - b2) / 2
m0 = cH * D
m1 = cB * D / g - k * m0
m2 = cL * D / (g*g) - m0
```

Per-sample tick (states `s1`, `s2`):

```
t1 = 1 / (1 + g*(g + k));  t2 = g*t1;  t3 = g*t2
v3 = x - s2
v1 = t1*s1 + t2*v3
v2 = s2 + t2*s1 + t3*v3
s1 = 2*v1 - s1
s2 = 2*v2 - s2
y  = m0*x + m1*v1 + m2*v2
```

- `g, k, m0, m1, m2` are linearly interpolated per sample across each control block
  from the previous target to the new one, and `t1..t3` recomputed while they move.
  Any `g > 0, k > 0` is a stable section, so every intermediate value is safe.
- Coefficient interpolation is only for small moves of one design. Switching a band
  in or out, or to a different shape or slope, crossfades the **whole cascade**
  against the dry signal (5 ms). Sections must never be faded one by one: a cascade
  often pairs a very high-gain section with a very low-gain one, and fading them
  separately lets the pair get out of step (measured: over 100 dB of overshoot).
- Guard: if `1 + a1 + a2 <= 1e-12` (pole at DC) fall back to a transposed direct
  form II biquad for that section.
- **Test**: for 10 000 random stable coefficient sets the SVF impulse response
  equals the direct-form biquad's to within `1e-9`.
- First-order sections use a one-pole trapezoidal integrator derived the same way.
- SIMD: stereo pairs of the same band are processed as one `double[2]` vector
  (SSE2/NEON). Do not vectorise across sections (serial dependency).

## 5. Natural mode

Identical band design, run at a higher internal rate so the response follows the
analog prototype through 20 kHz:

| Host sample rate | Internal rate | Latency (samples) |
|---|---|---|
| 44.1, 48 kHz | 4x | 76 |
| 88.2, 96 kHz | 2x | 13 |
| 176.4 kHz and above | 1x (same as Zero Latency) | 0 |

2x is not enough at 44.1/48 kHz. Measured worst error for ordinary settings
(12 dB/oct, Q 0.7 to 4, ±9 dB, band anywhere from 20 Hz to 20 kHz, base rate
44.1 kHz): shelves 2.3 dB at 1x, 0.96 dB at 2x, 0.23 dB at 4x; bells 1.2, 0.26,
0.07 dB; cuts 2.0, 0.10, 0.02 dB.

Resampling: linear-phase half-band FIRs (Kaiser, about 100 dB stop band), polyphase.
The first stage has 139 taps (flat to 20 kHz at 44.1 kHz); later stages, and the
single stage at 88.2/96 kHz, have 27. A round trip through a stage delays by its
half-length in input samples (69 or 13). In the 4x chain one extra sample at 2x
makes the total a whole number: 69 + 7 = 76.

When no band is active the output is the input delayed by the latency, bit for bit;
the resamplers keep running so a band can come in without a gap. A phase-mode
switch reconfigures the engine at a control-block boundary and fades the output in
over 10 ms. CPU cost of the bands is 4x (or 2x) that of Zero Latency.

Verified by `tests/unit/natural_tests.cpp`: in the top octave at 44.1 kHz the error
against the prototype is 0.09 dB in Natural against 1.20 dB in Zero Latency for the
same settings.

## 6. Linear and mixed phase

**One stage for all channels.** Every linear-phase band of a stereo pair collapses
into a 2x2 matrix of zero-phase (real) responses:

```
[L']   1 [ (Hm+Hs) Hl   (Hm-Hs) Hr ] [L]
[R'] = - [ (Hm-Hs) Hl   (Hm+Hs) Hr ] [R]
       2
```

`Hl`, `Hr` are the products of the stereo, left and right bands; `Hm`, `Hs` of the
mid and side bands. This is exactly "left/right bands, then mid/side bands" in a
single convolution stage, so the latency is paid once. Without mid or side bands
the off-diagonal kernels are zero and skipped.

**Kernel design** (worker thread), for each of the four responses:

1. Sample the response on `2N` uniformly spaced bins from 0 to `fs` using the
   prototype magnitudes (above Nyquist mirror). The values are real and may be
   negative (the `Hm-Hs` terms).
2. Inverse FFT, keep the `N` taps around the centre, apply a Kaiser window
   (`beta = 9`) **centred on tap `N/2`**. A window centred half a sample off leaves
   the kernel slightly asymmetric and a flat response slightly off unity.
3. Cut into partitions of `P` taps and store each partition's spectrum.

`N` at 44.1/48 kHz: 4096, 8192, 16384, 32768, 65536 for Low to Max; `P` = 512.
Both double per rate octave. **Latency `N/2 + P`**: the kernel's centre plus one
partition of blocking in the convolver. A convolver with a zero-latency head would
remove the `P`; it is a possible refinement.

**Convolution**: uniformly partitioned overlap-save, FFT size `2P`, with a
frequency-domain delay line of input spectra shared by all four kernels (`of::FirLane`).

**Threads.** The audio thread posts the set of linear-phase bands through a mailbox
guarded by a try-lock it never waits on. The worker designs into the kernel slot
the audio thread is not using and publishes it; the audio thread swaps at a block
boundary and crossfades old to new across that block. The audio thread never
writes a kernel slot. With no linear-phase bands the lane is a pure delay read
straight from the delay line, and a design made for another quality that arrives
late is dropped. Nothing is allocated after `prepare`.

**Idle.** With nothing active in either path the output is the delayed input, bit
for bit.

**Mixed mode**: bands with `lin` on go to the linear-phase lane, the others run in
the minimum-phase lanes ahead of it. Latency is that of the lane.

**Not built yet:** dynamics for bands in the linear-phase lane (planned: a
4096-tap difference kernel per dynamic band, `K = H(G0+R)/H(G0) - 1`, mixed in by
the detector; research item R-5). Until then a band's dynamics do not run while it
is linear; in Mixed mode, leave dynamic bands unflagged. All Pass bands have no
effect in the lane.

Verified by `tests/unit/linear_tests.cpp`: exact latency, mirror-symmetric impulse
response, response within 0.1 dB of the prototype from 60 Hz to 19 kHz at Medium,
channel separation for left and side bands, and Mixed with no flagged band equal
to Zero Latency plus the delay.

## 7. Dynamic bands

Applies to Bell, Low Shelf, High Shelf, Tilt Shelf. Per band:

1. **Detector input**: detector bus (internal pre-EQ signal or external sidechain),
   channel chosen by placement (L, R, M, S; Stereo uses the louder of L and R).
2. **Detector filter**: second-order band-pass at the band's `f0` with
   `Q = clamp(q, 0.5, 8)` for Bell; 12 dB/oct low-pass at `f0` for Low Shelf;
   12 dB/oct high-pass for High Shelf and Tilt. With `scfree`, a band-pass at
   `scfreq`, `scq`.
3. **Level**: squared signal, one-pole average with 5 ms time constant, converted
   to dB once per control block.
4. **Threshold**: `T = thr`, or in auto mode `T = L_slow + offset`. `L_slow` is the
   power average of the detector level over 3 s *(tune)*, frozen while the level
   is below -70 dBFS, initialised to -30 dBFS.
5. **Gain computer** (soft knee `W`, ratio `R`), with `x = L - T`
   (`x = T - L` for trigger Below):

```
over = 0                                    if 2x < -W
over = (x + W/2)^2 / (2W)                   if |2x| <= W
over = x                                    otherwise
target = sign(range) * min(over * (1 - 1/R), |range|)
```

6. **Ballistics**: one-pole smoothing of `target` in dB at control rate, attack
   coefficient while `|target|` grows, release while it shrinks:
   `coef = exp(-controlBlock / (tau * fs))`.
7. **Apply**: the band is redesigned each control block with gain `G + dyn`, and
   the kernel interpolates coefficients across the block. The current `dyn` is
   published for the UI.

Time resolution is one control block (0.67 ms at 48 kHz); attack values below that
behave as one block. With lookahead on, the audio path is delayed by the lookahead
time and the detector is not.

`sc_listen` routes the selected band's filtered detector signal to the output.

**Built so far:** everything above with the internal detector or the external
sidechain (per band; a band set to External falls back to the plugin input when
no sidechain is connected), plus band solo. The detector filter is a plain
12 dB/oct band-pass, low-pass or high-pass. The free detector filter, lookahead
and sidechain listen are not built yet. In Natural mode the detector runs at the
host rate on the undelayed input, which gives it about 0.8 ms of look-ahead at
44.1/48 kHz. Verified by `tests/unit/dynamics_tests.cpp`.

## 8. Spectral bands

One shared STFT lane serves all spectral bands of a channel.

- Frame `N = 2048` (at 44.1/48 kHz, scaled with rate), hop `N/4`, square-root Hann
  analysis and synthesis windows, output scaled by 1/2. Latency `N`.
- A second STFT analyses the detector bus with the same framing.
- Per band and bin `k` with detector level `L_k` (dB):
  - **Absolute**: `x_k = L_k - T`, threshold as in §7 (auto supported, per band).
  - **Resonance**: `x_k = L_k - E_k - rel`, where `E_k` is the detector power
    spectrum smoothed over one octave in log frequency and
    `rel = jmap(thr, -90, 0, 0, 24)` dB. Auto threshold is ignored.
  - `target_k = sign(range) * min(softKnee(x_k) * (1 - 1/R), |range|) * w_k`,
    where `w_k = |dB_i(f_k; gain = range)| / |range|` is the band's own shape used
    as a 0..1 weight.
  - Smooth `target_k` across frequency with a Gaussian of width `sres` octaves,
    then across time with attack and release (coefficients from the hop time).
- Sum the dB targets of all spectral bands per bin, convert to linear gain,
  multiply the complex bins of the audio STFT (zero phase), resynthesise.
- The static part of a spectral band (`gain`) is a normal band in its IIR or FIR
  lane.
- When no spectral band is active the lane is bypassed and removed from latency.

## 9. Character stage

Off (bit-transparent) when Clean. Otherwise 4x oversampled (linear-phase FIR,
latency reported), `d = 1 + 7 * drive` *(tune)*:

- **Tube**: `y = (tanh(d*x + b) - tanh(b)) / d`, `b = 0.15 * drive`, followed by a
  5 Hz DC blocker. Even and odd harmonics.
- **Iron**: +6 dB low shelf at 80 Hz, `y = x / (1 + |d*x|^2.5)^(1/2.5)`, inverse
  shelf. Level-dependent low-frequency thickening, odd harmonics.

Both are unity gain for small signals. Voicing is research item R-4.

## 10. Output section

Both auto gain modes are built (48 points rather than 128 for the curve estimate, recomputed at most every eighth control block; a one-channel band counts for half). Verified by the `[autogain]` unit test.

- **Auto gain, Curve**: `comp = -10 log10( sum w_j 10^(H_j/10) / sum w_j )` over 128
  log-spaced points from 20 Hz to 20 kHz, `H_j` the composite static response in dB
  averaged over channels, `w_j` equal per log step times a K-weighting magnitude.
  Recomputed on parameter change, smoothed over 50 ms.
- **Auto gain, Loudness**: BS.1770 K-weighted loudness of delayed dry and of wet,
  3 s window; `comp = clamp(L_dry - L_wet, -12, +12)` dB, one-pole smoothed with
  `tau = 2 s` *(tune)*, frozen while `L_dry < -60 LUFS`.
- Output gain, balance (equal-power above centre attenuation only: the louder side
  stays at 0 dB), polarity invert.
- **Bypass**: 10 ms crossfade between wet and delayed dry.
- **Delta**: 01 §4.5.
- Meters: per-channel peak (with 1.5 s hold) and RMS (300 ms), published once per
  block.

## 11. Smoothing and control rate

- Continuous band parameters are smoothed at control rate with a one-pole filter,
  `tau = 15 ms`, in the natural domain: log frequency, dB gain, log Q. A band is
  redesigned only in control blocks where a smoothed value moved by more than
  `1e-4` relative.
- Enabling, disabling, adding or deleting a band, and placement changes: the band's
  cascade crossfades with the dry signal over 5 ms, per channel.
- Shape and slope changes: the band fades out to dry (5 ms), waits until every one
  of its channel filters is idle, loads the new design, and fades in (5 ms). A
  true old-to-new crossfade with a spare cascade is a possible refinement.
- The first control block after a reset or `prepare` starts settled: no fades, no
  smoothing from stale values, so offline renders start correct from sample 0.
- Output gain and auto gain: per-sample linear ramps.
- Sample rate or block size change: all state cleared, kernels redesigned before
  the first block is processed (worker job awaited in `prepareToPlay`, which is not
  a real-time call).
