# 05 User interface

Visual source of truth: the mockup linked in the README (artboards "Main window"
and "Design tokens"). This file specifies behaviour, structure and the numbers the
mockup cannot carry.

## 1. Principles

1. The display is the instrument. Chrome is dark and quiet; colour is reserved
   for bands, the accent and warnings. The look is **neon arcade**: lit elements
   (curve, nodes, dial arcs, the 0 dB line, active buttons, meter segments) carry a
   soft halo of their own colour, the grid is tinted indigo, the plot has faint
   scanlines and the output meter is an LED ladder. Halos are built from layered
   strokes, not blur effects, so they cost little and work in every renderer.
2. One white composite curve. Each band has its own hue from a fixed 8-colour
   cycle, and its number is always printed on its node, so colour is never the
   only identifier.
3. The selected band's controls live in a **docked band dock** under the display.
   Nothing floats over the curve except a small value tag.
4. Every value can be dragged, scrolled, typed and reached by keyboard.
5. Vector only. No bitmaps, no skeuomorphic knobs. Gradients only for the input
   spectrum fill and the spectrogram ramp.

## 3. Window and scaling

- Design size 1280 x 800. Minimum 1180 x 560 for now (the dock's eight dials need the
  width; the 800 x 500 target needs the paged dock described below). No maximum. Free aspect ratio through
  the host's resize or the corner grip (`setResizable(true, true)` with a
  `ComponentBoundsConstrainer`).
- UI scale 50 to 200 % (menu and Ctrl/Cmd + `+`/`-`), applied with an
  `AffineTransform` on the editor's content component. Scale and size are saved
  per instance and as the user default.
- Full-screen toggle opens the same content component in a borderless desktop
  window on the current monitor; Esc returns.

Layout at design size (all regions stretch horizontally; only the display
stretches vertically):

| Region | Size | Contents |
|---|---|---|
| Top bar | height 52 | Logo, preset selector, undo/redo, A/B/C/D, phase mode, analyzer menu, instances, settings, full screen |
| Display | fills | Grid, analyzer, curves, nodes, value tag, piano strip (optional, 18 px at the bottom) |
| Output column | width 76 | Peak readout, L/R meters, output dial, Auto gain, Delta |
| Band dock | height 168 | Band chips, solo/bypass/delete, shape picker, slope, placement, filter dials, dynamics mode and dials |
| Status bar | height 30 | MIDI learn, latency, hint text, display range, analyzer tilt, UI scale |

Below 1000 px width the dock's dynamics dials move to a second page reached with a
"Filter / Dynamics" switch. Below 620 px height the dock collapses to a 44 px strip
of band chips with a pop-up dock.

## 4. Display

### 4.1 Mapping

- Frequency: log, 16 Hz at the left edge to 24 kHz at the right (bands can be
  dragged from 10 Hz to 30 kHz; nodes outside the view pin to the edge with an
  arrow).
- Gain: linear in dB, range ±3, ±6, ±12 or ±30 dB, 0 dB at 48 % of the height.
  With auto-range on, the display steps up when a node is dragged past the edge.
- Analyzer has its own dB scale (04 §1.2), shown on the left when hovered.

### 4.2 Layers, back to front

1. `GridLayer`: cached to an image; repainted only on resize or range change.
2. `AnalyzerLayer`: pre fill, post line, sidechain line, overlays from other
   instances, or the spectrogram image. Repaints at frame rate while audio flows.
3. `CurveLayer`: selected band fill (16 % of band colour) and outline, dynamic
   range target (dashed, band colour), live dynamic gain (solid band colour that
   moves between static curve and target), spectral band region (hatched),
   composite curve (2 px, plus a 7 px 12 % glow). In M/S or L/R situations where
   channels differ, two composite curves are drawn: the second at 60 % opacity
   with a `L R` / `M S` tag at the right edge.
4. `CollisionLayer`: strips from 04 §2.4.
5. `NodeLayer`: one child component per used band (hit area 28 px, visual 22 px).
6. `OverlayLayer`: value tag, rubber band, sketch stroke, spectrum-grab handles.

Curves are evaluated with `ResponseEvaluator` at one point per horizontal pixel
(max 2048) on the message thread, only when a band parameter changed. Each layer
is its own `Component` with `setBufferedToImage` where static, so an analyzer
frame does not repaint the grid.

### 4.3 Node states

| State | Drawing |
|---|---|
| Normal | Filled circle in band colour, dark number |
| Hover | +2 px ring at 40 % |
| Selected | 2 px gap, 2 px ring in band colour |
| Bypassed | Outline only, number in band colour |
| Dynamic / Spectral | Second concentric ring; the ring's arc length shows live dynamic gain relative to range |
| Linear (in Mixed mode) | Small square notch at the top of the node |
| Soloed | Everything else in the display dims to 35 % |

Placement is shown as a 2-letter tag (`L`, `R`, `M`, `S`) under the node when it is
not Stereo.

## 5. Band dock

Left to right (see mockup):

1. **Bands**: chips for every used band (number + colour dot), a `+` chip, count
   `n/32`. Under them Solo, Bypass, Delete for the selection.
2. **Shape**: 10-icon segmented picker, slope menu, placement segmented
   (`ST L R M S`), and in Mixed mode a `MIN / LIN` toggle.
3. **Filter dials**: Freq, Gain, Q.
4. **Dynamics**: mode segmented (Static, Dynamic, Spectral), then Threshold (with
   an `Auto` toggle under it), Range, Attack, Release. A disclosure opens the
   second row: Ratio, Knee, Trigger, Detector source, Free detector filter with
   its Freq and Q, Spectral mode and resolution, Sidechain listen.

Controls that do not apply to the current shape or mode are dimmed to 35 % and
skipped by Tab.

With several bands selected, dials show the value of the last-selected band and
edits apply **relatively** to all (frequency by ratio, gain and range by
difference, Q by ratio). Discrete controls apply absolutely. A mixed state shows a
dash.

**Dial** (`of::Dial`): 270 degree arc, 4 px stroke, track in `line`, value arc in
the band colour. Bipolar parameters fill from the centre. No pointer line, no cap.
Value text sits under the arc and is the text-entry target.

## 6. Interaction

### 6.1 Pointer, in the display

| Gesture | Result |
|---|---|
| Double-click empty area | Add band. Shape by position: left 6 % Low Cut, next 10 % Low Shelf, right 6 % High Cut, previous 10 % High Shelf, otherwise Bell. Gain from the click's vertical position |
| Drag node | Frequency and gain. Shapes without gain move in frequency only |
| Shift + drag | Fine (x0.1) |
| Alt + drag | Lock to the dominant axis |
| Ctrl/Cmd + drag vertically | Q |
| Wheel over node or selection | Q (Shift = fine) |
| Ctrl/Cmd + wheel | Gain |
| Drag the outer ring of a dynamic node | Range |
| Double-click node | Open value entry for frequency; Tab moves to gain, Q |
| Alt + click node | Toggle bypass |
| Ctrl/Cmd + double-click node | Reset gain to 0 dB |
| Right-click node | Context menu: shape, slope, placement, dynamics mode, phase, split to L/R or M/S, invert gain, solo, bypass, delete |
| Click empty area | Deselect |
| Drag empty area | Rubber-band select |
| Shift + click node | Add to or remove from selection |
| Hold on analyzer 600 ms | Spectrum grab (04 §1.4) |
| Pencil tool + drag | Sketch (04 §3) |
| Right-click empty area | Display menu: range, analyzer options, piano strip, add band here |

A drag is one undo step and one automation gesture per touched parameter.
The pointer is hidden and warped back on release for unbounded fine drags on
dials (`setMouseCursor` none + `Desktop::setMousePosition`), except on Wayland
where it stays visible.

**Solo** (button, or hold `S`): replaces the output with the selected band's
audition signal: Bell, Notch, Band Pass listen through a band-pass at the band's
frequency and Q; shelves and cuts listen to the region they affect. Solo is
momentary state in the engine, cleared when the editor closes.

### 6.2 Keyboard (when the editor has focus)

| Key | Action |
|---|---|
| Tab / Shift+Tab | Next / previous band by frequency, then on into the dock |
| 1..9, 0 | Select band 1..10 |
| Arrow left/right | Frequency ±1/12 octave (Shift: 1 cent x 10; Ctrl: 1 octave) |
| Arrow up/down | Gain ±0.5 dB (Shift: 0.1; Ctrl: 3) |
| `[` / `]` | Q down / up by 10 % |
| Enter | Type value of the focused control |
| Delete / Backspace | Delete selection |
| B | Toggle bypass of selection |
| S (hold) | Solo |
| D | Cycle dynamics mode |
| A | Add band at 1 kHz, selected |
| Ctrl/Cmd+Z, Shift+Ctrl/Cmd+Z | Undo, redo |
| Ctrl/Cmd+A | Select all bands |
| Ctrl/Cmd+C / V | Copy / paste bands as JSON on the system clipboard |
| Ctrl/Cmd+D | Duplicate selection |
| T | Toggle band table |
| F | Full screen |
| Esc | Cancel gesture, close panel, leave full screen |

Keys are only consumed when the editor has keyboard focus; unhandled keys are
passed to the host. A setting "Keyboard shortcuts" can turn single-letter keys off
for hosts that need them.

## 7. Value entry

`of::ValueParser` accepts, case-insensitively:

- Frequency: `850`, `850hz`, `1.2k`, `1k2`, note names `A4`, `C#3`, `Bb2`, with
  cents `A4+20`. Tuning reference A4 = 440 Hz (setting).
- Gain, range, threshold: `-3`, `+2.5`, `-3db`.
- Time: `15`, `15ms`, `0.2s`.
- Ratio: `4`, `4:1`, `inf`.
- Q: number; `oct 0.5` converts bandwidth in octaves to Q.
- Relative edits: a leading `*` or `/` multiplies or divides, `++` or `--` offsets
  (`*2` doubles a frequency, `--1.5` lowers a gain by 1.5).

Invalid input shakes the field and restores the old value.

## 8. Panels

- **Preset browser**: drop-down under the top-bar selector; folders, search,
  favourites, "Save", "Save as", "Set as default", "Reveal in file manager".
- **Band table** (`T`): docked sheet over the lower half of the display. One row
  per used band; columns for every per-band parameter that applies; cells are
  editable with the same parser; sortable by frequency or band number.
- **Instance panel**: 04 §2.3. Slides in from the right, 320 px.
- **History**: list of undo steps with labels; click to jump.
- **Match**: reference source, capture buttons, band-count slider, Apply.
- **Settings**: theme, scale, renderer, frame-rate cap, shortcuts, tuning
  reference, default display range, analyzer defaults, hub visibility, MIDI.

Panels are plain child components, never separate native windows (pop-up windows
break in several hosts). Menus use `PopupMenu` with
`withParentComponent(editor)`.

## 9. Accessibility

- Every interactive component overrides `createAccessibilityHandler()`.
- Nodes expose role `slider` with name "Band 4, Bell, 3.2 kilohertz, minus 1.5
  decibels, dynamic" and a value interface bound to frequency; gain and Q are
  reachable as child value interfaces.
- The band table is exposed as a `table` with row and column headers, which gives
  screen-reader users the whole EQ without the graphical display.
- Dock controls have name, value text with units, and step actions.
- Focus order follows visual order; focus is always visible (2 px accent outline).
- Announce on change: band added or removed, phase mode and resulting latency,
  preset loaded.
- Nothing is conveyed by colour alone; a reduced-motion setting disables analyzer
  ballistics animation easing and the node hover tween.

## 10. Rendering and performance

- Frame clock: `juce::VBlankAttachment`, capped at 60 fps (setting: 30/60/display).
  When no audio flows and no pointer moves, nothing repaints.
- Renderer: platform default (Direct2D on Windows, CoreGraphics on macOS). On
  Linux, and optionally elsewhere, attach a `juce::OpenGLContext` to the display
  component only. A setting falls back to software rendering.
- Budget on a 4K display at 200 % scale: display repaint under 4 ms on the message
  thread, measured in the bench suite with a recorded analyzer feed.
- Paths for curves and spectra are rebuilt in place (`Path::clear` keeps capacity)
  and stroked with `PathStrokeType` 2 px, mitred joins off.
- The editor holds no audio-thread locks; closing the editor at any time is safe.

## 11. Class map

| Class | Responsibility |
|---|---|
| `PluginEditor` | Owns `Theme`, content component, scale transform, panels |
| `ResponseDisplay` | Hosts the layers, pointer gestures, coordinate mapping (`DisplayMap`) |
| `BandNode` | One node; forwards drags to `BandController` |
| `BandController` | The only UI code that writes band parameters: gestures, undo transactions, add/delete/duplicate, relative multi-edit |
| `SelectionModel` | Selected band set, last-selected band, change broadcast |
| `BandDock`, `Dial`, `Segmented`, `ShapePicker`, `ValueField` | Dock widgets, each bound to a parameter through an attachment that retargets when the selection changes |
| `OutputColumn`, `LevelMeter` | Meters and output controls |
| `TopBar`, `StatusBar` | Chrome |
| `of::LookAndFeel` | Menus, tooltips, scrollbars, text editors in theme style |
